About this project

Unofficial fan project · Updated

One rule: we never invent a fact.

Everything you see on the scoreboard, delay feed and game page is pulled from a named, linkable official source. When two official sources disagree the row gets a 🚩 flag instead of being silently "corrected." Forecast-risk chips are a fixed, printed rule over the official forecast — not a prediction of whether a delay will happen. Expected restart times are never inferred from scheduled first pitch, from weather clearing, or from a reporter's speculation.

How it works

This is a zero-dependency static site hosted on GitHub Pages. There is no backend server, no database, and no API key baked into the page. Every data request goes directly from your browser to a public, CORS-enabled official endpoint:

  • Every ~5–20 seconds (depending on whether games are live) your browser polls the statsapi.mlb.com schedule for the selected date, then pulls play-by-play advisories and box-score notes for any game showing a delay.
  • Every ~5 minutes the NWS / ECCC / Open-Meteo forecast at each ballpark is refreshed; active weather alerts poll every ~2 minutes.
  • Every 15 minutes a GitHub Actions workflow scans the official MLB RSS feeds (league + 30 clubs), 7 independent news outlets, and the r/baseball community feed, then builds a JSON snapshot of delay/weather headlines. Your browser refreshes that snapshot once a minute and shows the latest scan run's status with a direct link to the workflow run.

Chat-style delay feed

The Delay Feed is organized as a live, chat-style feed with the newest and most urgent information at the top:

  • ⏸ DELAYED NOW strip: any game where MLB's official status currently shows a delay, suspension, or "About to Resume", with the reason and how long it has been going. Expected restart is explicitly labeled "not confirmed by this app" until an official source announces it.
  • Delay rows (⏱): a row for each delay segment in the play-by-play, with the full timeline of status-change advisories.
  • Postponed / suspended rows (📅): official reason plus reschedule / resume dates.
  • Forecast rows (🌧): one per game, with the risk chip, peak precipitation hour, and a collapsible hourly table for the game window.
  • Alert rows (⚠): active NWS/ECCC weather alerts at the ballpark, grouped by alert ID so one warning covering multiple parks appears once with all affected games listed.
  • Observed rows (👁): status flips this browser noticed between polls — labeled with the browser's clock, never as an official timestamp.
  • Written reports inbox: publisher headlines matching delay/weather keywords, refreshed from the server-side RSS snapshot every minute.

Weather integration

Every game card on the scoreboard and every forecast row on the feed shows:

  • A forecast-risk chip (⛈ High / 🌧 Moderate / 🌦 Low / ☀ Clear / 🏟 Covered / ❔ No data) derived from fixed, printed rules (see below). The rules are also displayed on every game page.
  • The worst hour in the game window (precipitation chance + short forecast + park time).
  • Count of active NWS alerts, with severe warnings highlighted in red.
  • MLB's own game-time weather string (condition, temperature, wind) when published.
  • Roof status (Dome / Retractable — open or closed / Open air), from venue.fieldInfo.roofType and MLB's weather string.

The forecast-risk rules are:

  • HIGH — max hourly precipitation chance ≥ 60% in the game window, or thunderstorms with ≥ 40% chance, or an active Tornado / Severe Thunderstorm / Flash Flood Warning at the ballpark.
  • MODERATE — max chance 30–59%, or any thunderstorm mention, or an active Watch / Advisory.
  • LOW — 10–29% with no thunderstorms.
  • NONE — below 10%.
  • COVERED — fixed dome, or retractable roof reported closed by MLB.
  • UNKNOWN — no forecast could be fetched (reason shown).

The game window is one hour before scheduled first pitch to four hours after (or to the final out once the game is complete).

Written reports — what is and isn't done

Important: Headlines in the written-reports inbox are review candidates, not verified restart announcements. A deterministic linker may attach a game when the headline uniquely identifies one game on the selected slate, and may quote an explicit restart/first-pitch time with the original evidence string — both remain review aids. Always click through to the official article (and the club's own MLB.com page or verified account) before treating a reported restart time as confirmed.

What is automated:

  • RSS feeds are fetched by a scheduled GitHub Action and parsed conservatively (only the standard RSS 2.0 fields: title, link, pubDate, author, description).
  • Items are surfaced when their title or description contains words from a documented delay vocabulary (delay, postponed, suspend, tarp, rainout, resume, inclement, first pitch…) or weather vocabulary (rain, thunder, lightning, storm, tornado, flood, snow, drizzle…).
  • Every headline links to its article and its publisher RSS feed; the exact words that matched are shown on the card so a reviewer can see why it was surfaced.
  • Duplicate URLs are de-duplicated; future-dated, older-than-24h, and dateless items are flagged.
  • Deterministic game linking (assets/js/match.js): a headline is linked to a gamePk only when named team(s) uniquely identify one game on the selected slate. Doubleheaders without an explicit game-number cue, non-opponents, and three-plus clubs abstain (left unlinked on purpose). Matched phrases are shown as evidence.
  • Explicit restart/first-pitch quotes: only announcement phrasing ("restart at 8:35 p.m. ET", "first pitch now set for 7:10pm", "targeting an 8:30 restart") is extracted, with the matched substring retained verbatim. Speculative wording ("hoping to", "could resume", "around") is rejected; 12-hour clocks without a.m./p.m. leave the 24-hour hour unresolved so nothing is invented.

What is not automated (see Limitations):

  • No force-linking of ambiguous headlines — historical references, spring training, multi-club roundups and doubleheaders without a game number stay unlinked.
  • No invented restart times from weather forecasts, scheduled first pitch, or soft estimates ("hoping to get underway around 8:30"). Only explicit announcement text is quoted.
  • No reading of X/Twitter, Facebook, Instagram, Threads or Bluesky posts — those platforms have no keyless public read API (re-verified 2026-09-22). Reddit is attempted server-side on every scan (its public JSON is keyless); anonymous access from the build network currently answers HTTP 403, so the scan lists it as an unavailable source with a link to the subreddit instead of skipping it. If the network ever allows it, posts flow with no code change.

🚩 Flagged irregularities

Whenever two official sources disagree, or an unexpected shape is encountered, the row gets a flag with the rule code and a plain-English explanation. Examples:

  • duration-mismatch — play-by-play delay segments sum to something different from MLB's own delayDurationMinutes figure.
  • boxscore-mismatch — the printed box-score delay duration disagrees with the schedule field.
  • reason-conflict — detailedState, statusCode letter, and reason field don't agree.
  • non-weather — a delay whose reason is Power, Injury, Ceremony, etc. (still shown, just labeled).
  • nws-no-coverage / non-government-source — the venue falls back to ECCC or Open-Meteo.
  • mlb-wet-forecast-dry / mlb-dry-forecast-wet — MLB's first-pitch weather string contradicts the government forecast.
  • sparse-schedule — the official schedule reports far fewer games for a date than its neighbours (observed live 2026-09-22: 3 games on 2026-09-21 vs 15 on both neighbours). Shown with the counts and a link to that date's schedule JSON; may be a legitimate sparse slate or incomplete schedule data — a reviewer decides.

Flags are never resolved silently. They stay on the row until a human reviewer checks the sources.

Known limitations

This is a useful partial implementation, not exhaustive social monitoring. The following are real, current constraints:

  • SOCIALPartial social-media ingestion. Reddit (r/baseball) is attempted on every scan — it has the only keyless public read path of the platforms named in the project goals — but anonymous access from the build network answered HTTP 403 on 2026-09-22, so it is reported as an unavailable source (with a link to the subreddit) rather than skipped. X/Twitter, Facebook, Instagram, Threads and Bluesky have no keyless public read API (re-verified 2026-09-22): X locked down anonymous reads in 2023 and Meta requires an authenticated Graph API. Ingesting them requires storing server-side credentials in GitHub Actions secrets — never in the static page (see Next steps).
  • PAGESThe published snapshot is not deployed until a one-time admin switch. The repo's GitHub Pages is still on legacy branch publishing, so the workflow-built snapshot (which holds the written reports) is not served on the public site. The workflow cannot switch Pages mode itself (admin-only, HTTP 403). Until a repository owner enables Settings → Pages → Build and deployment → Source: GitHub Actions, the Delay Feed shows the latest scan run's status with a direct link to the run, and prints the exact steps.
  • ETARestart times are quoted, never invented. Explicit announcement phrasing is extracted with the original evidence string and optional zone label; speculative estimates ("hoping to", "around 8:30") and forecast-clearing times are rejected. 12-hour clocks without a.m./p.m. leave the 24-hour hour unresolved. Times are not converted across time zones and are never treated as official MLB status.
  • RSSRSS scanning is 15-minute scheduled, not real-time. GitHub Actions scheduled jobs can be delayed by up to ~15 minutes during load; Pages publishing adds another latency window. This is not a continuous monitoring service.
  • GEOSome venues have no government forecast coverage. International venues (London, Mexico City, Santo Domingo, Tokyo) fall back to Open-Meteo model data and are flagged as non-government. The Athletics' temporary Sacramento venue and other special-event parks depend on coordinates MLB publishes; when absent the forecast is flagged no-coordinates.
  • CORSECCC GeoMet browser CORS could not be exercised from the build sandbox. Rogers Centre is coded to fall back to Open-Meteo (flagged) if the ECCC request fails in a real browser.
  • FEEDSClub RSS feed availability varies. If a club's feed is down the failure is listed in the snapshot but that club's headlines will not appear until the next successful scan. Always cross-check the club's MLB.com page for active delays.
  • HISTORYBrowser-observed transition history lives only in localStorage (per date, kept for 7 days). Server-side history of observed delays across all visitors is not retained.
